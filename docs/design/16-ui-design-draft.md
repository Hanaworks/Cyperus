## 设计方向

采用已经确定的传统 VS Code 工作台结构，为连续浏览本地 Markdown 服务。标题、菜单、导航和正文之间保持直接、稳定的空间关系，以排版、对齐与组件状态建立层次。

本稿按用户最新截图采用标题与菜单同一行、顶部没有搜索框；用户明确确认文件、搜索、大纲的活动栏保留左侧，同级切换；文档通过标签切换；全局状态与双主题切换位于底部。当前布局依据见 [阅读工作台](15-reader-workbench.md)，现有功能边界见 [UX 执行记录](../dev/ux-workbench-progress.md)。

第一稿具体提案是统一树行、图标、字体、边距和状态表达，并补齐首次打开、文件浏览、搜索、大纲、加载与失败画面。Git、编辑、终端和性能工作继续保持后续范围。

| 侧栏 | 默认宽240，允许180–min(480, 窗宽−340) | 沿用阅读区域约束；可收起，分隔条可拖动和键盘调节 |

## 文件浏览与标签

资源管理器分为“打开的编辑器”和根目录两个可折叠组。分组文字和根目录名使用同一基线；展开箭头占固定宽度，文件图标和文件名不随选中状态跳动。

文件名一行显示，过长时省略，完整路径通过悬停说明可读。选中项整行着色。“打开的编辑器”列表中的关闭图标固定占位，悬停、选中或键盘进入时显示，不能因为图标出现而挤动文件名。磁盘目录树不提供关闭或删除文件的按钮。

活动标签显示文件名与关闭按钮；非活动标签降低文字强调，关闭按钮在悬停或焦点进入时出现。长标签省略，标签过多时横向滚动；激活项进入可见区域。原型演示基础切换与关闭，完整重排、右键、最近关闭、跨会话恢复继续留在既有后续任务中。

关闭活动标签时优先激活右邻，无右邻时激活左邻，并将键盘焦点移到该标签；关闭非活动标签保持原阅读焦点。如果键盘焦点本就在被移除的非活动项内，则转到活动标签，避免焦点丢失。最后一个标签关闭后回到开始画面。焦点规则属于本稿补充的交互提案，不代表当前所有关闭路径已经具备该行为。

目录刷新、改变根目录等动作保留在资源管理器标题右侧，不占用全局标题栏。读取失败时就地提示并提供重试入口；打开其他文件仍可继续。

目录还需区分未打开文件夹、读取中、空目录、部分条目未显示、不可访问和不支持预览的文件。读取中保留组标题并禁用重复刷新；空目录显示“文件夹为空”；截断时说明“条目较多，部分内容未显示”；非Markdown文件保持文件名可辨认并标明不支持预览，不使用看似可打开的状态。

## 搜索与大纲

搜索仅作用于当前文档。左侧输入框高28px，匹配计数与上下条按钮在同一组内，显示当前项与总数。正文用普通匹配高亮和当前匹配高亮区分，跳转后让实际命中文字进入视口。

第一稿在计数下方展示可点击的匹配摘要，作为搜索结果展示方式的新增提案；当前产品仅有匹配计数与前后跳转，摘要列表待评审后另行决定。

未输入关键词时使用简短说明；零结果显示“没有找到匹配内容”；未打开文档时输入框禁用，并说明先打开文档。Enter与Shift+Enter切换结果，Ctrl+F打开并聚焦正文搜索。

匹配数量属于搜索本身的局部反馈，放在搜索操作附近。全局路径、编码、章节与文档数量仍统一在底部。

大纲与文件浏览占用相同侧栏区域。标题层级通过缩进表达，当前章节高亮；长标题单行省略，完整标题可读。没有标题时展示空状态，不生成虚假的章节。

本稿补充分开两种大纲空状态：“打开文档后显示大纲”与“此文档没有标题”。搜索沿用跨标签保留关键词的现有行为；建议再次按Ctrl+F选中已有关键词，Escape优先关闭弹层或菜单，其次从搜索输入返回正文焦点。收起搜索时取消高亮，再次打开恢复关键词与匹配。这些焦点细节作为待评审提案。

## 底部状态与弹层

状态栏左侧为运行状态与环境信息入口，随后显示根目录或活动文档路径；右侧依次为章节数、文档数、编码、界面主题和正文主题。路径过长时优先缩短目录部分，保留文件名；文件名自身超过全部可用空间时再尾部省略，悬停可读完整路径。保留文件名优先级是本稿规格，原型当前仅演示整体省略，需在实施时补齐。主题名称要能直接识别，不能只放无标签的图标。

界面主题改变应用外壳，正文主题改变文章；纸张主题仍是正文选项。选择后直接显示结果，不增加确认步骤，不改变文章解析或当前文件。

环境信息从状态栏向上展开，显示真实环境数据；帮助菜单进入同一弹层。Escape关闭后焦点回到发起入口，点击外部关闭并保留用户新选择的位置。菜单和弹层都使用同一组边框、阴影和行高规则。

加载状态在底部显示“正在打开 文件名…”，标签可同时有加载图标。错误需要明确对象和可执行动作：文档失败可以重试或关闭；目录失败在目录位置处理。全局操作提示的关闭按钮只关闭提示，不误关已打开文档。

首次加载尚无正文时保留当前文件标签与底部进展提示，正文区域不伪造进度或继续显示上一文件的内容。失败页说明当前文件不可读取并给出重试 / 关闭；具体原因只出现一次，避免正文和横幅重复整段错误。切换到其他已经打开的标签仍可继续阅读。

## 窗口适配与评审标准

桌面基准覆盖1440与1024宽；640为当前应用最小窗口宽度。640宽时保持三层结构、主题切换和菜单可用，路径先缩短，侧栏由用户收起或调窄。设计展示小于640的宽度仅用于对话预览，会折叠侧栏，不构成应用新增移动端范围。

侧栏拖动和键盘调宽采用同一窗口约束，避免键盘调节把正文挤出可用宽度。底部先让路径缩短，再压缩控件间距；640桌面基准保持编码、计数、两套主题与环境入口可达，不通过新增收纳菜单改变当前全局信息组织。

设计评审应逐项确认：阅读区域是否舒适；标题、菜单、文件树与标签是否对齐；悬停、选中和键盘焦点是否容易区分；主题入口是否清楚；路径变长、标签变多、无结果、加载和失败时是否仍可理解与操作。

2026-11-06按用户指令落实本稿结构和基础细节。搜索摘要、完整标签能力、持久化、Git等仍按文中后续边界处理；实际功能以代码与验证记录为准，不把原型演示计为已经实现。后续结构变更仍先调整设计稿。
