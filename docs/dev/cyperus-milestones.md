# Cyperus 目标与里程碑

更新于 2026-11-19。本文是交付路线的当前入口。既有 Code OSS 试用版、实现记录和 Tauri 基线继续提供对照。

Cyperus 首先是本地 Markdown 阅读器。默认打开渲染预览，按需编辑源码。目录树、搜索与标签用于在项目里找文件和继续阅读。静态 HTML 保留预览能力；JSON、YAML 以可读的原文展示为先，按需考虑结构导航。

| 阶段 | 当前状态 | 交付物与验收门槛 |
|---|---|---|
| 1. Code OSS 集成 | 已有可运行候选，作为当前集成和体验基线 | Windows 试用包可启动。Markdown、静态 HTML、目录浏览、搜索、两种视图的大纲跳转和基础编辑可用。中英文配置各通过 37 项桌面集成检查。正式发布验收另见执行记录。 |
| 2. VSIX 扩展验证 | 下一阶段，待打包验证 | 产出可离线安装的 Markdown 扩展 `.vsix`。在未修改的桌面 VS Code、隔离配置中安装，验收默认预览、源码切换与保存、预览和源码的大纲跳转、正文搜索。确定用户能选择或恢复原有的 `.md` 默认编辑器，并记录适用的宿主版本、包体积以及功能差异。 |
| 3. 精简独立版验证 | 待 VSIX 明确复用边界后推进 | 产出独立 Windows 试用包，可单独打开文档或项目文件夹，提供 Markdown 预览、大纲、正文搜索和基础编辑。复测本地文件打开、项目与阅读状态恢复，以及换目录升级后设置和记录的延续。用实际出包大小、冷启动到可读及稳定后的内存，与阶段 1 做同条件对比。 |

## 阶段之间怎么复用

- **先复用现有扩展。** VSIX 以已经接入 Code OSS 的阅读器为起点，复用 Markdown 渲染、预览页、大纲、正文搜索和源码切换。阶段 2 先验收 Markdown。静态 HTML 已在桌面候选中提供，无需为了验证扩展而接管原版 VS Code 的 HTML 打开方式。
- **宿主能力单独评估。** 当前从文件全局搜索结果直接定位到渲染段落，靠 Code OSS 将源行号传给预览。VSIX 优先采用原版 VS Code 的行为，实测搜索结果落点。大纲的源码行跳转、预览锚点跳转和正文搜索不依赖这个补丁。
- **独立版复用渲染和交互。** 已有 Tauri/WebView2 基线可先做对照。复用正文渲染、组件、语法着色和测试文档，单独适配文件访问、窗口、搜索和持久化。原生目录树、编辑器和窗口生命周期等能力按独立版体验验收。Windows 的 `.md` 文件关联和项目内的默认预览分别验收。

## 体积基线

| 产物 | 当前证据 | 说明 |
|---|---:|---|
| Code OSS 双语候选 | **499.9 MB** 展开 | 按交付清单与清单文件本身统计，不含启动后产生的用户数据。内置阅读器目录约 **18.7 MB**。 |
| 独立 VSIX | 待实测 | 记录 VSIX 文件大小和安装后的扩展目录大小。VS Code 已由用户安装，单独列出这一前提。 |
| 历史 Tauri M1 | **6.4 MB** ZIP / **11.1 MB** 展开 | 复用 Windows WebView2，证明分发体积有显著降低空间。功能与性能按各自验收记录比较，不能按包大小换算。 |

Windows x64 比较时统一记录压缩产物、解压目录、是否依赖预装运行时，以及同一文档的冷启动和稳定内存。轻量独立版以显著缩小交付包为目标，具体容量门槛待样品实测后确定。
