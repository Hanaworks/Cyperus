# ADR-003 — 性能阈值与大文件策略

- **状态**:Proposed（建议用于 M1，待负责人批准）
- **日期**:2026-11-04
- **决策者**:项目负责人
- **影响范围**:渲染队列、分段、HTML / SVG 缓存、watcher、基准与 M1 验收

## 背景

**2026-11-07 更新：** 当前已实现单 Worker 排队、HTML LRU 与分段呈现，并完成真实多标签及 50 轮原生回收验证。最新数据与未通过项见 [M1 验收记录](../dev/m1-acceptance.md)；下述 M0 数据保留为历史，不代表当前发布版。本 ADR 仍为 Proposed，不静默调整目标。`native-summary.json` / `native-tree.csv` 是可重跑的 latest 输出，当前精确发布证据使用带 M1 运行标识的独立目录和原始 CSV。

本轮已有浏览器开发环境数据、真实原生字节 IPC 与发布版事后 idle 的 RSS / CPU 证据。原生 AC-10 已测且未达标；冷启动、端到端首屏 / 完整渲染、交互 P95、大文档峰值、真实 watcher 和多标签预算仍待 M1。不能将浏览器 mock、单次 IPC、设计目标或未测字段写成原生性能达标。

### 已测数据与口径

浏览器观测来源为 `benchmarks/results.csv`（本轮共 34 行，其中一行为独立的原生 idle）：Chromium 156.0.8078.4、Vite dev、1440 × 900、同机仍有协作开发负载。cold 是新 context 首次打开，warm 是同 context 再次打开；计时从 `openText` 起算，不含进程 / WebView2 创建、磁盘读取或原生 IPC。DOM ready 是全量插入 + 双 rAF，不是分块首屏，也不含异步 Mermaid。

其他观测：

- `mermaid-100` 两轮 DOM ready 为 490.7 / 61.6 ms；随后显式 renderAll 阶段为 4320.5 / 3060.3 ms，终态均 done=100 / error=0 / pending=0。该阶段不是完整打开耗时，也没有并发 1 / 2 / 4 对照。
- `code-heavy` 旧夹具为 22,637 bytes / 200 块，旧行保留；已修正为 2,104,318 bytes / 200 块并单独 cold / warm 实测。500 公式夹具输出 HTML 1,261,972 bytes。
- 100 KB 开关 50 轮、每检查点关闭后等 5 s、不强制 GC：第 5 / 50 轮 RSS 为 782.602 / 809.492 MiB，比率 1.034；只覆盖本次浏览器单文档场景。
- 稳定代码下静置 60 s：已打开 100 KB 的 browser 树 CPU 累计 471.875 ms，空外壳 899.125 ms；两次均未达到 AC-10 的 100 ms 目标，不由两次差值推导正文 CPU 成本。

旧 22 KB 的低耗时不能代表这组长代码成本。新数据表明，源码小于 8 MiB 仍可能产生昂贵高亮与大量 HTML；仅做 DOM 分块不能消除 8–10 s 的解析 / 高亮阶段。M1 须另测高亮成本与调度策略，原生同规模尚未测量。

原生发布探针 `native-m0-baseline.json`（08:35 UTC，WebView2 156.0.4314.58，保留的初次记录）验证了四档 `ArrayBuffer` 类型与 byteLength：

|---|---:|---:|
| 100 KB | 103,414 | 3.7 |
| 1 MB | 1,049,596 | 15.5 |
| 10 MB | 10,486,765 | 109.4 |

这些时间只覆盖探针的读取 / IPC 窗口，没有同时采集读取峰值或完整渲染口径，不能推出 50 MB 的首屏、滚动或产品支持上限。

原生 idle 证据为 `native-summary.json` / `native-tree.csv`（08:36 UTC，发布 EXE SHA256 `D7A0502AFE77E1B63A8758B503CC52FA6D9CE6DCAFEA79587B0A2F84087B5DD0`）：IPC 与七份固定夹具运行后，最后活动文档为 `tabs/a.md`，未强制 GC；60,483.189 ms / 71 样本，RSS 峰 / 末 845.711 / 682.078 MiB，CPU 累计 3628 ms（单逻辑核 5.998361%）。**AC-10 未达标**，超过静置约 60 s 的 100 ms 目标。该峰值仅属于事后的 idle 窗口，既不是之前 50 MB 读取峰值，也没有覆盖 50 MB DOM 渲染。

## 候选方案

| 方案 | 结论 |
|---|---|
| 全量 DOM + content-visibility，所有规模通用 | 现有 10 / 50 MB 的 P95 与 RSS 已暴露问题，不能作为大文档最终策略 |
| 按顶层语义边界分段 + 邻段预热 + content-visibility | 延续设计，控制同时驻留 DOM；需实现与测量后验收 |
| 通用虚拟滚动 / 增加多个解析 Worker | 本轮没有对照收益；可变块高度、重排与并行内存需要额外设计，不作为当前默认 |

## 决策

M1 采用 **单解析 Worker、代次守卫、分段 + content-visibility、显式缓存预算**。当前 M0 仍是全量解析 / DOM 插入，没有实现分段或完整多标签预算。下列数值分为工程初值与待原生标定的性能目标，不将“目标”描述为“已达到”。本 ADR 获批也不代表全部性能验收通过。

### M1 工程门槛

| 项 | 初值 / 必须行为 | 依据与验收 |
|---|---|---|
| 自动分段 | 原始 UTF-8 字节数 **≥ 8 MiB** 启用；允许用户主动开启 | 延续 `08` 的 8 MB 初值并明确字节口径；10 / 50 MB 全量 DOM 已出现高延迟。阈值尚未证明最优 |
| 宿主保护边界 | 文件 **> 64 MiB** 返回 `tooLarge` 强制分段标志，**> 200 MiB** 拒绝读取 / 打开 | 延续文档生命周期设计的保守边界；M1 接通强制分段与提示。标志不等于 M0 已实现分段，也不构成 ≤ 200 MiB 的支持承诺 |
| 分段驻留 | 按 h1 / h2 / hr 与平衡 token 边界切分；当前段 + 相邻 1 段；远离超过 3 段转等高占位 | T39 需覆盖长列表 / 表格 / 无标题与巨型单块；不可截断未闭合结构。分段不免除全文 tokenize 成本 |
| 首屏分块 | 先取平衡顶层边界，累计约 32 KiB 或 200 token，再继续；最多 8 条结果消息 | 延续 `08` 初值。1 MB cold DOM ready 已达 627.3 ms，T24 / T39 需测真实首块时刻，不以 warm 168.1 ms 宣称 cold 达标 |
| HTML 缓存 | 全部标签保留的序列化 HTML 配额 **48 MiB**；按 UTF-8 字节计账，非活动标签 LRU 逐出 | T28；当前页优先。活动结果单份超过预算时不得继续保留全量 HTML 缓存，转分段 / 不缓存路径；配额不是 JS heap / RSS 上限 |
| 活动 DOM | 同时只保留当前文档 DOM；非活动文档仅保留受预算约束的数据 | T24c / T28；10 / 30 / 100 文档实测逐出及重开，不将单文档 50 轮替代多标签 |
| Mermaid | 可见图优先，并发 **2**，每图等待 **5 s**，SVG 缓存至多 **40 条**，按源码 hash + 主题区分 | 延续设计初值；超时不等于库任务已取消，不释放仍在运行任务的并发槽。需补并发度与缓存驻留测量 |
| watcher 去抖 | **120 ms**，同路径窗口内合并，版本 / 代次守卫拒绝旧结果 | `03` 设计初值；T21 / T22 验证真实覆写、原子替换、连续保存后再标定。显式 reload 三次不证明此值足够 |
| Worker 调度 | 单 Worker 串行、同文档新任务替换待处理旧任务；丢弃过期结果 | T23 / T24；结合长代码数据评估高亮成本与调度；销毁重建作为长任务阻塞时的备选，先测 Shiki 重建成本，不声称物理取消已实现 |

8 MiB 是渲染器常规分段初值，64 MiB 是宿主强制标志，两级用途不同；两者都不能单独保证长代码等小源码 / 大输出场景流畅。200 MiB 是当前宿主保守拒绝边界，没有证据支持提高或宣称该范围全部可读。50 MB 是当前压力夹具规模，不是产品支持承诺。缓存字节配额与 DOM / 图片 / SVG / Worker 内存分别管理。

### M1 暂定原生验收目标

以下沿用 `08-performance.md` §1 的设计初值，用于 M1 开发与回归；**没有原生实测达标证据，尚不能冻结为产品性能承诺**。正式标定须固定 release 构建、WebView2、字体 / 窗口与夹具，保留冷暖和原始行；调整目标需更新本 ADR。

| 指标 | 100 KB | 1 MB | 10 MB | 50 MB（分段） |
|---|---:|---:|---:|---:|
| 冷进程启动 → 首屏 | < 800 ms | < 800 ms | < 1.5 s | < 3 s |
| 打开后首块可读 | < 150 ms | < 250 ms | < 700 ms | < 2 s |
| 完整渲染（分段需遍历全部段） | < 400 ms | < 1.2 s | < 6 s | < 30 s |
| 交互 P95 | < 50 ms | < 50 ms | < 80 ms | < 100 ms |
| 进程树 RSS 峰值 | < 220 MiB | < 260 MiB | < 480 MiB | < 900 MiB |

浏览器开发树已经高于这些 RSS 初值，不能作为原生失败 / 达标的等价证据。滚动 scrollTop → rAF 与真实输入 / 标签切换须分列；Mermaid 全图终态须单列，不与 DOM ready 混写。分段模式的首块、当前驻留 DOM ready 与遍历全部段后的累计渲染 / 完成时刻须分列，不能把尚未渲染的惰性段就绪记成完整渲染；不要求全部 DOM 同时驻留，计时由 T39 补采。

## 后果

### 必须遵守

- 先保留原始 CSV 与失败行，再作结论；未测值不写 0。`first_paint_ms` / `full_render_ms` 必须在 notes 标清阶段，不能将 DOM ready 或 read / IPC 改名为冷启动首屏。
- M1 性能验收同时要求：50 轮原生开关后第 50 / 5 轮 RSS 比率 ≤ 1.3（本轮未测）；打开后静置 60 s 的原生进程树 CPU 累计增量 < 100 ms（本轮实测 3628 ms，未达标，需修复后重测）。
- 普通规模不引入后台解析 / 轮询；释放观察器、图表层、Range、事件与 Blob URL。泄漏与多标签预算必须分别测量。

### 需要验证

- T15 / M1：补固定 release 的原生冷启动 / 首块 / 完整 DOM ready / P95，以及大文档读取 / 渲染 RSS 峰；定位并修复原生 AC-10 后重测。至少重复 3 轮并报告每轮与范围，不能用本轮探索单次声称统计显著。
- T21 / T22：真实 watcher 三种保存方式、删除 / 替换与版本事件；T17 / T19 补 registry / 路径与权限错误闭环，验证 120 ms 去抖的合并正确性与延迟。
- T24c / T28：10 / 30 / 100 文档的切换、不变内容不重解析、HTML LRU、关闭回收；大文档与图表缓存共同占用。
- T39：8 MiB 两侧与 10 / 50 MB 分段、无标题 / 巨型块、主题 / 窗口重排下的滚动稳定性；另做 10 MB content-visibility A/B。
- T23 / T24：补约 2 MiB 长代码的原生同口径测量，并基于已有浏览器高亮成本验证调度策略；单独测 Worker / Shiki 初始化与销毁重建。另补 Mermaid 并发 1 / 2 / 4 对照。T14 不纳入本轮门槛。

### 回滚成本

工程初值可通过集中配置调整，但不能静默放宽性能门槛。改变分段结构或缓存计账会影响源码映射、搜索、滚动恢复与标签切换，需同步回归；是否更换宿主另按 ADR-001 决策。
